# 模型配置、直接发送与流式创作对话规格

日期：2026-10-14。产品范围依据两轮已确认的 Q1–Q10；用户已确认以现有浏览器流程为主要验收，连接真实 API 和独立测试库，仅在模型 HTTP 边界使用可控替身，并用 PostgreSQL 测试覆盖迁移和并发。

## Problem Statement

管理员添加模型时，必须先创建独立模型供应商，再维护模型配置和多类供应商说明，直接填写模型地址与密钥的简单需求被拆成多个步骤。同一供应商新增另一个模型还会退役已有模型配置，使创作者无法同时选择多个模型。

创作者点击发送后，经常被“确认本次创作的发送范围”弹窗打断。作品所有者需要重复批准，编辑者无法独立完成连续对话和生成；只隐藏弹窗也无法解决问题，因为后端调用仍依赖逐次外发确认。

回复虽然可以从上游流式读取，但页面要等完整结果才显示，创作者无法边读边讨论或及时停止。切换模型、长篇作品上下文、停止后的部分回复和多人同时调用缺乏一致的可见行为。已有配置、凭证、对话及任务必须在改进过程中保留，不能要求用户重新录入或清空作品。

## Solution

管理员直接在模型配置中维护显示名称、接口类型、模型标识、base_url、API key 和可选参数。支持 OpenAI 兼容与 Anthropic 原生，默认 OpenAI 兼容；每个模型独立启停和更新不可变配置版本，同一地址可同时添加多个模型。

作品所有者和编辑者在创作工作区选择模型后直接发送对话、发起正文生成或选段重写，取消发送范围弹窗及逐次所有者审批。发送区展示模型和可展开的创作上下文范围；查看者只读，管理员的模型管理能力不额外授予作品阅读权。

用户发送后立即看到自己的消息与回复占位，回复逐步显示，支持停止。模型切换继续同一段历史，每条回复标明所用模型；选择按用户和作品记住，不影响其他协作者。上下文默认包含消息、近期对话、设定、大纲和当前正文目标，整部正文由明确选项控制，超限提示调整范围。

同一作品的 AI 调用串行执行。普通对话允许继续编辑正文，回复绑定发送时快照；正文生成继续锁定输入，成功仅替换目标并产生整部作品的生成版本。停止或断线保留部分回复和状态，默认不作为后续模型上下文。保留并迁移已有数据，更新模型配置不改变当前请求，主动停用模型停止未完成调用。

## Implementation Decisions

- 本规格实现已确认的 Q1–Q10，采用 ADR-0011；逐次外发确认和所有者预览审批按该 ADR 取消。作品成员访问边界、已确认设定、结构化正文、整部作品版本和发布导出规则继续沿用原决策；正文输入锁按已更新的 ADR-0009 执行。
- 调整模型管理、创作工作区、模型 HTTP 适配、创作上下文构造、对话生命周期、生成任务执行、工作区读取、调用记录、数据库迁移及备份恢复模块，复用现有账号、会话、CSRF 与作品权限检查。
- 模型配置具有稳定模型身份与独立启停状态，配置版本独立于其他模型递增且不可变。新增模型不退役其他模型；同名或同地址模型不因名称或地址相同而合并为一个身份。
- 模型创建与更新接口直接接收显示名称、接口类型、模型标识、base_url、API key 和可选参数，不再要求供应商引用。更新不回填原密钥；保留凭证与明确轮换操作必须能够区分，不能把空表单意外写成空密钥。
- 新版管理与创作流程不依赖独立供应商配置及其启用说明。删除旧关联时保护历史引用；是否短期保留历史兼容结构属于实施选择，不能继续要求用户配置供应商，也不能以清空数据库完成迁移。
- API 向普通成员返回可用模型元数据和启停状态，历史回复可读取已退役版本的模型归属；凭证既不出现在管理响应也不出现在作品响应、流式事件或普通日志。
- OpenAI 兼容与 Anthropic 原生保持明确协议分支，各自使用正确的地址拼接、认证与请求结构。模型身份、目标地址与认证不能被可选参数覆盖；具体 URL 规范化方式在实施阶段确定并由契约测试验证。
- 管理员更新配置后，新调用使用最新有效版本；已开始调用继续使用原版本和凭证。模型启停属于稳定模型身份的状态，主动停用必须能影响该模型各版本下尚未完成的调用，不能只检查版本是否退役。
- 迁移保存已有模型版本、凭证密文、对话、生成任务和调用记录的原始引用及归属。原按供应商维护的版本需要建立可重现的模型身份映射，不能把曾配置的不同模型误认为同一模型；只迁移原可用状态，不自动激活历史退役配置。
- 备份与恢复识别新模型结构及旧历史记录；继续遵守既有备份不包含模型密钥的规则，不能借此功能向备份新增原密钥。数据库原地迁移保留现有密钥，跨环境恢复仍按原规则重新配置凭证。
- 模型选择按用户与作品记住，“包含整部正文”选项也需记住；存储方式由实施阶段选择，不能跨账号误用选择、覆盖协作者设置或把 API key 存入浏览器偏好。
- 请求明确绑定所选模型、调用种类、消息或指令、正文目标和上下文选项。客户端选择只影响下一次调用；所选模型不可用时阻止发送并明确提示，不自动更换模型。
- 创作对话、正文生成、选段重写及其重试不再要求逐次外发确认标识。授权依据是启用账号、有效作品成员权限、作品可用状态和模型启用状态；取消前端弹窗必须与后端契约一起交付，不能自动伪造所有者授权。
- 默认创作上下文包括当前消息、近期完整对话、创作设定、大纲及当前选中的集、场景或片段。未选正文目标时不附带正文；整部正文仅通过发送区明确选项加入。服务端生成实际发送内容，界面摘要与该内容一致。
- 上下文使用需要参与本次调用的已保存资料，并固定外发输入快照和模型配置版本。已确认设定仍作为有效约束；未确认资料用于讨论时保持草稿语义，临时指令不直接改变已确认设定。
- 近期完整历史可包括其他模型回复；未完成、已停止的回复默认排除。历史窗口、预算数值与估算方法在实施阶段确定，需可测试并通过界面说明所用范围；超限要在调用前明确提示调整，不静默丢弃正文或已确认设定。
- 对话创建接口须支持持续传送内容，并暴露可持久化调用标识、所用模型版本、回复内容和状态。发送即显示用户消息与回复占位，随后逐步更新；不得用后台聚合后的完整 JSON 回应冒充浏览器流式输出。SSE 或其他具体传输方式属于实施选择，不是新的产品决策。
- 对话读取与工作区读取能够返回已完成和未完成消息、模型归属及状态，使刷新后读取已保存内容。对话内容属于作品资料；调用记录仍仅保存必要元数据，不重复保存提示词与回复原文。
- 停止操作由服务端终止请求并阻止后续成功提交，保留已保存的部分文字和已停止状态。连接中断、模型停用及其他失败须形成明确终态，保留未完成内容；流断开不能让调用无限占用作品忙碌状态。
- 对话失败保留输入并提供手动重试，不自动重新外发。幂等标识用于区分同一次请求重发与用户主动新尝试；重复点击、网络超时及重发不能重复创建消息或上游调用。
- 服务端原子执行同作品活动调用检查，统一涵盖对话与正文生成；忙碌时明确拒绝额外调用并保留客户端输入，不静默排入另一轮创作。原有全局容量规则可继续限制不同作品的实际执行。
- 普通对话期间允许编辑正文，回复绑定发送时快照；后续正文 revision 变化不能直接丢弃回复，对话提交也不能覆写这些编辑。对话记录及其调用状态不构成正文生成版本。
- 正文生成保持三阶段有效确认、目标校验、指令、固定输入、作品输入锁、幂等与任务状态。成功只替换目标，非目标正文由服务端保留，然后形成整部作品的生成版本；失败、取消或无效结果不产生成功版本。
- 正文任务保持既有有限重试规则，但每次外发与结果提交继续验证账号、作品成员、作品、模型启用和取消状态，不再验证逐次外发确认。固定版本因正常配置更新退役不能等同于模型停用。
- 停止、连接中断、模型停用、账号停用、作品删除和成员权限撤销都需由服务端收口、释放活动调用并阻止失效请求提交。浏览器离线或关闭不能成为释放忙碌状态的唯一条件。
- 不改变现有发布、导出、成员管理、设定变更提案和恢复权限。只读查看者与非成员不能直接绕过界面发起调用，模型配置管理员也不能绕过作品访问控制。

## Testing Decisions

- 用户已确认主要验收入口为现有 Playwright 浏览器流程，使用真实账号权限、真实 API 和独立测试库；唯一外部替身边界是模型 HTTP 服务。数据库迁移和真实并发使用既有独立 PostgreSQL 测试补充。所有测试不得读取或修改本机实际作品库，也不调用真实付费服务。
- 优先扩展现有完整浏览器流程、模型 HTTP 契约、账号与作品权限、正文生成取消和 PostgreSQL 迁移测试；不另建一套覆盖相同逻辑的组件或内部函数测试体系。
- 好的测试驱动用户行为或公开 API，检查可见结果、实际发送内容和外部副作用；不断言私有状态、组件结构或实现内部方法调用次数。上游替身收到的请求数量可用于判断是否发生重复模型调用。
- 可控模型 HTTP 替身支持 OpenAI 兼容和 Anthropic 原生协议、分段输出、暂停继续、超时、断开和错误。以控制响应完成的方式证明第一段文字已显示，而非依赖固定睡眠或最终文本存在。
- 模型管理流程添加同一地址的两个模型并确认都可选择，更新一个不影响另一个；覆盖独立启停、凭证不回显、协议认证和非法参数无法替换身份信息。
- 两个浏览器成员在同一作品选择不同模型，验证偏好互不覆盖、切换保留历史、跨模型近期历史进入实际请求、历史回复保留版本归属，以及停用选择不被静默替换。
- 使用所有者、编辑者、查看者和非成员验证对话、生成及选段重写。检查前两者无需弹窗或逐次审批即可调用，后两者被服务端拒绝；管理员未获作品授权同样不能读取内容。
- 对正文目标为空、集、场景、片段及整部正文选项分别检查模型 HTTP 请求中的实际资料；用独特标记确认未选正文未被发送。覆盖上下文超限提示、近期历史范围和不完整回复默认排除。
- 浏览器验证即时用户消息、回复占位、增量文字、主动停止、连接中断、模型停用、失败保留输入及手动重试。重新打开作品或刷新后读取已保存部分内容和终态，停止后上游不能继续造成成功提交。
- 并发测试同时发起对话／对话、对话／生成、生成／对话及生成／生成，证明同作品只有一个调用实际执行；额外请求的忙碌错误与输入保留可见。用 PostgreSQL 验证服务端原子约束，不能只依赖单浏览器按钮禁用。
- 对话执行中保存正文，验证正文保存成功、回复不丢失且不会覆写编辑；正文任务期间保存正文应遵循输入锁，终态后恢复编辑。不同作品在容量允许时能分别执行。
- 请求执行中更新模型地址或密钥，检查原请求仍使用固定配置、新请求使用新配置；主动停用则阻止新请求并收口未完成调用。覆盖账号停用、作品删除和成员撤权后不会继续提交。
- 使用代表性旧数据库运行真实迁移：保留多个供应商历史模型、退役版本、有效配置、加密凭证、对话、任务和记录，检查引用、可用状态和模型归属。覆盖 SQLite 开发库与独立 PostgreSQL；凭证验证通过测试密钥解密或替身认证完成，不输出密钥。
- 备份恢复测试覆盖新结构与旧记录兼容、历史引用、密钥不进入备份以及跨环境重新配置凭证的既有规则。不能只验证备份文件能打开。
- 生成和重写验证三阶段确认、结构校验、固定目标、取消、有限重试、非目标正文保留、成功整部作品版本及发布导出回归。删除逐次授权的旧断言，保留与本规格一致的权限、版本和数据范围断言。
- 保持现有前端类型检查与生产构建、后端行为测试及 Compose 启动健康检查；新增验收应能在现有自动化环境执行，流式服务经实际同源访问路径也能持续传送。

## Out of Scope

- 新增独立模型供应商配置、逐次外发审批、所有者预览链接审批或独立通知中心。
- 恢复已退役模型为可用状态、清空数据库重建或重新录入全部已有模型。
- 新增其他模型协议、自动探测协议、自动抓取服务可用模型列表或自动更换模型。
- 多模型同时回答、自动模型路由、独立模型聊天分支或实时多人共同输入。
- 让查看者发起模型调用、让管理员绕过作品成员授权，或改变所有者专属的设定确认、审批、恢复、发布和导出权限。
- 自动采纳对话回复、让对话直接修改正文或已确认设定、把部分回复当作完整结果默认进入上下文。
- 静默发送整部作品、自动丢弃已选正文或已确认设定、自动重发失败对话。
- 改变结构化剧本块、最小片段重写边界、整部作品版本和发布记录的数据来源。
- 改变备份不包含模型密钥的规则、重建部署架构或真实付费模型验收。

## Further Notes

两轮用户均回答“全部同意”，Q1–Q10 产品决策无待定分支。本次 to-spec 只发布规格，不实现、部署或提交代码。浏览器主验收与 PostgreSQL 补充验收已由用户在本轮明确确认。

ADR-0011 是新规则依据；ADR-0004 的逐次外发确认和供应商启用说明、ADR-0010 的所有者预览审批已被替代。ADR-0002 的私有作品与成员权限、ADR-0003 的设定和生成版本、ADR-0005 的元数据调用记录、ADR-0006 的结构化正文和 ADR-0009 更新后的并发与输入锁仍有效。

现有实现仅按供应商维护活跃配置，对话使用逐次外发确认，上游流式内容被后端聚合后返回，对话后检查作品整体 revision；这些行为是需要改造的基线，不能视为新规则已经交付。具体数据映射、传输协议、持久化频率、超限估算与接口命名由实施者选择，并证明符合本文外部行为。

实施时优先保留现有测试与业务边界，数据库和接口改造需要同时考虑历史对话模型归属、正文任务、取消、备份及恢复；不可只交付管理页或删去弹窗。正式完成需通过上述验收，未实现的新设计不得写成现有能力。
