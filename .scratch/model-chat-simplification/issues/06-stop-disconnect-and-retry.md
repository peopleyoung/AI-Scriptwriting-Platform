# 06: 停止、断线恢复与手动重试

**What to build:** 用户可停止正在回复的对话，断线或失败后仍能读到已保存文字和状态，刷新可恢复查看，并明确点击重试后再调用。

**Blocked by:** 05：持续输出的创作对话。

**Status:** resolved

**用户故事覆盖：** 53–61。

依据已确认的模型配置、直接发送与流式创作对话规格及 ADR-0011。采用浏览器主验收、真实 API 与独立测试库，仅在模型 HTTP 边界使用可控替身；数据库迁移及并发由独立 PostgreSQL 测试补充。

- [x] 点击停止由服务端终止请求并阻止后续成功提交，保留部分文字和已停止状态，不只是停止页面渲染。
- [x] 断线及失败保留已保存内容和未完成状态，刷新可读取；活动调用被收口，作品不永久忙碌。
- [x] 已停止／未完成回复默认不进入后续上下文，完整历史仍可使用，用户可从页面辨别状态。
- [x] 失败保留输入，只有用户手动重试才新发请求；重试与原请求重发能区分，避免重复消息或重复调用。
- [x] 页面离线或关闭后服务端仍能结束调用；不依赖浏览器在线才能释放忙碌状态。
- [x] 可控替身验证主动停止、上游断开、刷新、后续实际上下文及重试；状态持久化和权限检查通过真实 API 验证。
