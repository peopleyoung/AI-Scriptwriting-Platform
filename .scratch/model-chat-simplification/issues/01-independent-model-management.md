# 01: 兼容迁移与独立模型管理

**What to build:** 管理员无需创建供应商，直接维护多个独立模型；创作者能读取新的可用模型，已有配置与作品历史保留。

**Blocked by:** None (can start immediately).

**Status:** resolved

**用户故事覆盖：** 1–16、79–83。

依据已确认的模型配置、直接发送与流式创作对话规格及 ADR-0011。采用浏览器主验收、真实 API 与独立测试库，仅在模型 HTTP 边界使用可控替身；数据库迁移及并发由独立 PostgreSQL 测试补充。

- [x] 管理员从单一模型配置入口创建、查看、更新和独立启停模型，不再要求供应商表单或说明。
- [x] 字段包含显示名称、接口类型、模型标识、base_url、API key 和可选参数，默认 OpenAI 兼容，支持 Anthropic 原生。
- [x] 同一地址添加 A、B 后两者均可选择，更新 B 不退役 A；同名或同地址不造成身份合并。
- [x] 模型具有稳定身份和独立不可变版本，密钥加密保存且不回显，保留与轮换密钥的操作可区分。
- [x] 对代表性旧 SQLite 与独立 PostgreSQL 数据库作兼容迁移，保留凭证、旧版本和原任务／调用引用；历史退役版本不重新启用。
- [x] 先扩展新的模型身份和配置形式，必要时保留旧调用的兼容桥接，确保现有对话、生成和恢复在过渡期仍可运行；彻底移除兼容路径由 09 执行。
- [x] 浏览器完成添加多个模型及更新流程，真实模型 HTTP 替身验证两种协议、认证及可选参数不能覆盖调用身份；凭证不进入普通响应或日志。
