# 模型配置与创作对话简化

日期：2026-10-14。
状态：两轮访谈 Q1–Q10 均获用户“全部同意”，设计分支已收敛；to-spec 已发布[正式规格](spec.md)，实施任务已完成，运行代码已完成改造。

## 用户提出的目标

- 去除独立模型供应商配置，保留模型配置，直接添加 base_url 和对应 API key。
- 添加多个模型后，创作对话支持模型切换。
- 点击发送后在对话框显示回复，不弹出“确认本次创作的发送范围”。
- 评估是否可以删除这个弹窗。

## 调查与评估

弹窗可以删除，但必须同时调整后端外发授权规则，不能仅隐藏界面。
现有规则只有作品所有者能创建外发确认，对话与正文生成都依赖有效确认。
2026-10-14 首轮确认：编辑者可直接发送，正文生成同时取消该弹窗。
ADR-0011 已记录替代 ADR-0004 的逐次外发确认及 ADR-0010 的所有者输入预览审批；已实现。

对话界面已有模型下拉选择，但目前同一供应商创建新的模型配置会退役其已有配置。
多个可同时选择的模型必须拥有独立身份，不能把另一模型的新增当成旧模型的版本更新。

现有 endpoint 支持服务地址并按协议补充请求路径。OpenAI 兼容与 Anthropic 原生
在路径、身份验证和请求结构上存在差异，仅凭 base_url 和 API key 不能可靠识别协议。

上游模型可以使用流式响应，但后端聚合成完整回复才返回；前端尚未逐步显示回复。
首轮已确认“在对话框直接输出”包含逐步输出。

当前对话发送的创作背景包括历史对话、设定、大纲和完整工作草稿。
第二轮已确认缩小默认上下文范围，并提供包含整部正文的选项，详见 Q6。

## 待确认的设计分支

无。具体接口、存储和上下文预算数值由实施阶段选择，必须符合已确认行为。

## 已确认决定

2026-10-14 用户对 Q1–Q4 回答“全部同意”。

- Q1：删除独立供应商配置；模型配置保留显示名称、接口类型、模型标识、base_url、API key 和可选参数。支持 OpenAI 兼容和 Anthropic 原生，默认前者。
- Q2：所有者和编辑者直接使用管理员启用的模型，查看者只读；发送区展示模型和上下文范围，可展开查看，不阻断发送。
- Q3：对话、正文生成与选段重写均删除发送范围弹窗；保留三阶段设定确认、生成目标与指令。
- Q4：点击发送立即显示用户消息和回复占位，逐步输出；支持停止，失败保留输入并提供重试。

2026-10-14 用户对 Q5–Q10 回答“全部同意”。

- Q5：模型切换继续同一段对话，历史不清空；每条回复标明模型。选择影响下一次发送，按用户和作品记住，不改变其他协作者的选择。
- Q6：默认当前消息、近期对话、设定、大纲和当前选中的集／场景／片段；无目标时不附带正文。包含整部正文是发送区选项并记住选择，超限明确提示调整，不静默丢弃正文或已确认设定。
- Q7：保留并迁移已有模型、密钥、对话和任务记录；模型独立启停和更新版本，新增 B 不停用 A；退役版本只保留历史，不自动重新启用，密钥加密保存不回显。
- Q8：停止或连接中断后保留部分回复，标记已停止／未完成，默认不进入后续模型上下文；停止结束请求，失败提供手动重试，刷新能读取已保存消息和状态。
- Q9：同一作品只执行一个 AI 调用，其他成员保留输入并看到忙碌状态；生成锁定输入，对话允许编辑正文但回复绑定发送时快照。
- Q10：当前请求固定原配置版本，更新只影响后续请求；主动停用模型阻止新请求并停止尚未完成的调用，保留中断状态。

结论记录于 `docs/adr/0011-direct-model-configuration-and-member-invocation.md`，完整设计见 `docs/model-chat-design.md`，术语已同步；运行代码已完成改造。

2026-10-14 to-spec：用户确认以现有 Playwright 浏览器流程为主要验收，连接真实 API 和独立测试库，仅在模型 HTTP 边界使用可控替身；独立 PostgreSQL 测试补充迁移和并发。正式规格已发布为 `spec.md`，实施已完成，包含 85 条用户故事及实现、测试和范围约束。
