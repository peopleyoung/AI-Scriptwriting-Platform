# 剧本写作平台规划

状态：需求访谈完成。已确认的产品边界与建议技术方案分别记录；进入实现前需完成技术评审。

## 一、目标与已确认需求

平台让用户通过与大模型交流，明确剧本主题、人物角色等创作决策，再由大模型创作剧本。

| 项目 | 已确认内容 |
| --- | --- |
| 首版使用范围 | 个人或内部团队使用，账号由管理员创建 |
| 首版剧本类型 | 中文短剧；同时支持竖屏微短剧与网剧短剧，通过模板配置区分 |
| 登录与权限 | 用户登录后使用平台，不同角色具有不同权限 |
| 管理员 | 可以写作、管理平台及进行模型设置 |
| 普通用户 | 可以写作，不能管理平台或修改平台模型设置 |
| 创作方式 | 用户与模型讨论创作决策，再由模型写作 |
| 创作确认 | 采用分阶段确认：创作简报、人物与故事大纲，再分段生成正文；关键设定变更需再次确认 |
| 作品访问 | 作品默认私有；管理员的管理权限不自动包含他人作品阅读权 |
| 作品协作 | 作品所有者可邀请查看者或编辑者；管理员仍需获得授权才能查看 |
| 作品所有权 | 创建者自动成为作品所有者；管理员同样遵守作品授权规则 |
| 协作者内容 | 查看者可读聊天、设定、大纲、正文和版本；编辑者可修改草稿和发起生成；所有者负责审批 |
| 登录 | 管理员创建账号；用户使用账号密码登录，首次登录修改初始密码 |
| 部署 | Docker 容器化部署 |
| 模型接入 | OpenAI 兼容接口与 Claude 原生 Anthropic 接口分别适配 |
| 模型选择 | 管理员维护可用模型列表；普通用户从已启用模型中选择 |
| 模板管理 | 管理员维护剧本模板；用户创建作品时选择模板并填写作品参数 |
| 协作者边界 | 编辑者可参与创作；作品所有者负责邀请、撤销、删除和所有权转移 |
| 设定变更 | 对已确认设定的修改先形成变更提案，经作品所有者确认后生效 |
| 数据发送 | 作品内容可发送给管理员启用的外部模型供应商，平台记录必要调用日志 |
| 版本管理 | 每次生成或修改形成可追溯版本，支持比较与恢复；发布或导出前需明确确认 |
| 导出 | 首版支持 Markdown 与 DOCX，导出前需完成版本确认 |
| 部署形态 | 首版使用 Docker Compose 单机部署，包含应用、数据库和文件存储 |
| 外部模型告知 | 调用前展示供应商、模型和数据发送范围，由作品所有者确认允许外发 |
| 账号生命周期 | 管理员可创建、停用、重新启用、重置密码和调整角色；关键操作留审计记录 |
| 生成粒度 | 先生成创作简报、人物和故事大纲，再按集/场景分段生成；支持选段重写 |
| 模板参数 | 模板提供集数、单集时长或字数目标、题材标签和输出格式默认值，作品创建时可调整 |
| 导出权限 | 只有作品所有者可导出正式稿；编辑者只能参与准备 |
| 调用记录 | 只保存供应商、模型、时间、状态、用量和错误等必要元数据；完整内容留在作品版本与对话中 |
| 首版规模 | 面向内部团队，目标不超过约 20 名并发创作者 |
| 备份与删除 | 每日备份数据库和作品文件，保留 30 天；删除先进入可恢复回收站，过期后永久删除 |
| 模型凭证 | 服务端加密保存；只有管理员可配置和轮换，普通用户不能读取原始密钥 |
| 界面语言 | 首版只支持简体中文界面、提示词和剧本输出 |
| 其他交付约束 | 暂无固定上线日期、预算或指定前后端技术栈 |

## 二、建议的产品组成

以下为讨论用的模块划分，具体功能边界待后续确认。

| 模块 | 建议职责 | 仍需明确 |
| --- | --- | --- |
| 创作工作区 | 组织一部作品的讨论、人物设定、大纲与正文 | 剧本格式、项目组织、导入与导出 |
| 创作决策管理 | 汇总创作要求，识别待确认与已确认的设定 | 用户确认节点、模型自主修改范围 |
| 剧本生成与修订 | 分阶段生成内容，根据反馈修订并保留版本 | 生成任务状态、失败恢复、版本规则 |
| 账号与权限 | 登录、管理员创建账号、按角色控制操作 | 密码策略、审计记录保留期限 |
| 平台与模型管理 | 配置可使用的模型及平台运行规则 | 模型用量与费用限制、凭证保管、故障处理 |

## 六、已确认的创作流程

1. 管理员创建账号并配置可用的剧本模板与模型。
2. 用户登录；首次登录修改初始密码。
3. 用户创建作品，选择竖屏微短剧或网剧短剧模板，填写作品参数。
4. 用户与模型讨论创作简报、人物和故事大纲。
5. 用户确认创作简报、人物与故事大纲，形成后续生成约束。
6. 用户按分段任务生成正文；每次生成或修改形成一个可追溯版本。
7. 作品所有者可以邀请查看者或编辑者；编辑者参与创作，查看者只读。
8. 对已确认设定的修改先提交变更提案；作品所有者确认后才影响后续生成。
9. 用户比较、恢复版本，明确确认后发布或导出。

## 八、建议系统架构

这是没有既有技术栈约束时的实现基线，不是已确认的技术选型。

| 层次 | 建议 |
| --- | --- |
| Web 应用 | React + TypeScript；创作工作区采用三栏布局：对话、设定/提案、正文/版本 |
| API 与领域服务 | Python FastAPI；将账号、作品权限、创作决策、生成任务、版本和导出拆成清晰的领域模块 |
| 持久化 | PostgreSQL 保存用户、权限、作品、设定、版本、任务和审计元数据；作品文件进入文件存储 |
| 异步生成 | Redis + 独立任务 worker；生成任务有排队、运行、成功、失败、取消状态，前端可轮询或通过 SSE 获取进度 |
| 模型适配 | 独立 OpenAI 兼容适配器与 Anthropic 适配器，统一为内部生成任务接口；供应商凭证只在服务端使用 |
| 导出 | Markdown 直接生成，DOCX 使用专用文档生成器；导出绑定已确认的剧本发布版本 |
| 部署 | Docker Compose 编排 Web、API、worker、PostgreSQL、Redis 和文件存储；备份目录不与应用容器同卷 |
| 安全与审计 | HttpOnly 会话、密码哈希、登录限流、服务端加密凭证、权限校验、审计记录；调用日志禁止写入完整提示词和模型原文 |

## 九、核心领域对象

- **User / Role**：账号和管理员、普通用户角色；账号状态包括启用、停用和首次登录待改密。
- **Work / WorkMember**：作品及其所有者、查看者、编辑者授权。
- **ScriptTemplate / WorkSettings**：管理员维护的模板与作品创建时复制的集数、时长/字数、题材和输出格式参数。
- **CreativeBrief / Character / Outline**：创作简报、人物和故事大纲；确认后成为后续生成约束。
- **LockedDecision / ChangeProposal**：已确认设定及待所有者审批的变更提案。
- **Conversation / GenerationJob**：创作对话和按集、场景或片段执行的生成任务。
- **WorkVersion / Release**：每次修改形成的版本，以及所有者确认可导出的正式稿。
- **ModelProvider / ModelConfiguration / ExternalTransmissionConsent**：供应商、已启用模型、模型配置和作品外发授权。
- **InvocationRecord / AuditRecord**：模型调用元数据和账号、权限、配置等关键管理操作记录。

## 十、实施阶段

1. **基础平台**：Docker Compose、账号登录、首次改密、管理员账号管理、角色和审计。
2. **作品与权限**：作品所有权、协作者邀请/撤销、查看者/编辑者权限、回收站。
3. **模板与创作决策**：两种模板、作品参数、创作简报、人物、大纲、确认设定和变更提案。
4. **模型生成**：OpenAI 兼容和 Claude 适配器、模型选择、外发确认、异步生成、失败重试和必要调用记录。
5. **版本与交付**：按集/场景/片段生成、选段重写、版本比较/恢复、正式稿发布、Markdown/DOCX 导出。
6. **运维验收**：每日备份和恢复演练、30 天保留策略、权限审计、Docker 部署文档和内部团队试用。

## 十一、首版验收标准

- 停用账号无法登录；首次登录必须修改初始密码；管理员关键操作有审计记录。
- 未获授权的用户（包括管理员）无法读取作品、聊天、设定、正文或版本。
- 查看者不能修改；编辑者可以参与创作和发起生成，但不能管理协作者、确认锁定设定或导出正式稿。
- 作品所有者可以确认设定、审批变更提案、比较/恢复版本、发布并导出 Markdown/DOCX。
- 外部模型调用前展示数据去向并取得作品所有者确认；调用记录不包含完整提示词和模型原文。
- OpenAI 兼容接口和 Claude 原生接口均能完成一次创作对话、一次分段生成和一次选段重写。
- 数据库和作品文件可从 30 天内备份恢复；回收站中的作品在保留期内可恢复。

## 十二、首版范围建议

纳入首版：

- 账号密码登录、首次改密、管理员创建与停用账号。
- 管理员维护两种剧本模板、可用模型和模型凭证。
- 作品创建、所有权、查看者/编辑者邀请与撤销。
- 创作简报、人物、故事大纲、已确认设定、变更提案。
- 分段生成、生成版本、版本比较与恢复。
- OpenAI 兼容接口与 Claude 原生接口适配，调用前数据外发确认和必要调用日志。
- Markdown 与 DOCX 导出。
- Docker Compose 单机部署及数据库、文件存储备份说明。

暂缓到后续：

- 公开注册、计费、多租户隔离。
- Kubernetes 或多节点弹性部署。
- 自动评估剧本质量、自动发布和无审批批量改写。
- 复杂组织架构、细粒度自定义角色和跨作品检索。
