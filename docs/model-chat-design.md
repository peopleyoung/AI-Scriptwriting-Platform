# 模型配置与创作对话设计

日期：2026-10-14。状态：两轮访谈 Q1–Q10 均已确认，九项任务已落地到代码；部署需使用新构建并执行迁移。决策依据见 [ADR-0011](adr/0011-direct-model-configuration-and-member-invocation.md)，访谈记录见[设计记录](../.scratch/model-chat-simplification/map.md)。

to-spec 已发布[正式规格](../.scratch/model-chat-simplification/spec.md)。用户已确认以现有浏览器流程为主要验收，模型 HTTP 边界使用可控替身，独立 PostgreSQL 测试补充迁移和并发。

## 模型管理

去除独立模型供应商配置入口，管理员直接添加模型。字段为显示名称、接口类型、模型标识、base_url、API key 和可选参数；默认 OpenAI 兼容，同时支持 Anthropic 原生。

每个模型有独立身份、启停状态和不可变配置版本。同一服务地址可添加多个模型，新增模型 B 不会退役模型 A；模型名称相同但地址不同的配置也可独立存在，显示名称帮助区分。更新地址、密钥或参数产生该模型的新版本，其他模型不受影响。

密钥由服务端加密保管，页面不回显原值，普通成员不读取凭证。当前调用固定发送时的版本；管理员更新配置不改变已发请求，主动停用模型则阻止新请求并停止未完成调用，保留中断状态。

保留并迁移已有模型、密钥、对话、任务和调用记录，不清空实际数据。历史配置与模型身份建立对应关系，旧退役版本只用于历史追踪，不自动成为可选模型；旧供应商关联的移除不能破坏历史记录的引用或备份恢复。

## 模型切换与直接发送

创作对话区提供模型选择，选择按当前用户与作品记住，不改变其他成员的选择。切换模型继续同一段作品对话，保留历史，每条回复标明使用的模型；新选择只影响下一次发送。未配置可用模型或原选择已停用时提供明确提示，不擅自替换为另一模型发送。

所有者与编辑者可直接发起对话、正文生成和选段重写；查看者只读。管理员启用模型不赋予其读取未授权作品的能力。服务端仍检查账号状态、作品成员权限、作品状态和模型启用状态。

删除“确认本次创作的发送范围”弹窗及逐次所有者审批流程，不自动伪造所有者授权。发送区持续显示当前模型和上下文范围，可展开查看实际范围，点击发送直接开始调用。正文生成继续要求三阶段设定有效确认、明确生成目标与指令。

## 创作上下文

默认内容为当前消息、近期对话、创作设定、大纲和当前选中的集／场景／片段；没有正文目标时不附带正文。发送区提供“包含整部正文”选项并记住选择，不增加确认弹窗。

上下文使用已保存资料，发送前同步当前需要参与的修改，并固定本次内容快照。已确认设定仍是创作约束，临时指令不能直接覆盖；未确认阶段的资料用于讨论时保留其草稿含义。

近期历史可以同时包含不同模型的完整回复；已停止或未完成回复默认不进入后续模型上下文。近期历史最多 12 轮完整成功对话，默认预算为 60000 字符，可通过 APP_CREATIVE_CONTEXT_MAX_CHARACTERS 调整；如选定内容超限，发送前明确提示调整范围，不静默丢弃正文或已确认设定。近期历史的范围在发送区可查看。

正文生成与选段重写绑定实际选择的目标及上下文，成功仅替换目标范围并产生覆盖整部作品的生成版本；未发送给模型的其他正文由服务端保留，不要求模型重新生成。

## 回复、中断与重试

点击发送立即显示用户消息和回复占位，随后逐步显示返回文字；前端必须消费后端持续返回的内容，不能只在后台读取上游流后一次显示。

用户停止、连接中断或模型停用时，保留已经收到的部分回复，显示已停止／未完成状态，默认不用于后续模型上下文。停止需要结束本次请求；已经完成的消息及已保存的部分内容、状态可在刷新后读取。

失败保留输入并提供手动重试，不自动重复发送对话。重复点击、网络重发和重试需要区分，避免把一次操作变成多次模型调用或重复消息。正文生成仍保留现有任务状态、取消及有限重试机制；每次尝试使用固定输入和模型版本，并重新检查成员、作品、模型及取消状态，不再依赖外发确认。

## 并发与编辑

同一作品一次只执行一个 AI 调用，覆盖创作对话和正文生成；其他成员看到忙碌状态，未发送输入保留，不由客户端静默排入另一轮调用。不同作品可在平台容量限制内分别执行。

正文生成期间按 [ADR-0009](adr/0009-work-input-lock-during-generation.md) 锁定作品输入修改，完成、失败或取消后恢复。普通对话期间允许编辑正文，回复仍对应发送时固定的快照；后续正文修改不能导致已收到的对话被丢弃，也不能使回复覆盖正文。

忙碌状态、取消与终态由服务端维护，多个浏览器和直接 API 调用都受同一约束。权限撤销、账号停用、作品删除或模型停用不能让未完成调用继续沿用失效权限。

## 验收边界

- 同一地址添加两个模型后都能选择，切换后历史仍在，回复显示真实所用模型；协作者选择互不覆盖。
- 所有者和编辑者直接对话、生成及重写，全程不出现外发弹窗；查看者与非成员不能发起调用。
- OpenAI 兼容和 Anthropic 原生都验证地址、请求结构和身份验证，密钥不出现在普通响应、页面或日志。
- 默认范围、无正文目标、整部正文选项与超限提示符合规则，检查实际发送内容，而非只检查界面文字。
- 回复逐步到达，停止和断线保留状态与部分内容；刷新可读取，后续上下文默认排除不完整回复。
- 两名成员同时请求时只有一个调用实际开始；普通对话期间编辑正文不丢回复，生成期间输入锁有效。
- 更新模型配置不改变运行中请求；停用模型停止未完成调用，原配置历史可追溯。
- 旧配置、凭证、对话、任务及备份兼容迁移，未退役其他模型，未将历史退役配置自动启用。

测试通过可控模型接口替身验证真实 API、数据库和浏览器流程，不需要付费模型调用。API 使用直接模型配置、持久化对话与 SSE；迁移保留历史供应商行作为外键桥接，公开供应商和逐次确认接口已删除。新备份为 format-2；旧 format-1 中从未保存的模型归属、任务及快照无法补造，原有作品和对话仍可恢复。
