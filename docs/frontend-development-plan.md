## 1. 交付目标与当前基线

交付一个可以从浏览器完成完整创作流程的中文内部工具：登录/首次改密 -> 创建作品 -> 邀请协作者 -> 对话与三阶段确认 -> 外发确认 -> 分段生成/选段重写 -> 保存与比较版本 -> 发布正式稿 -> Markdown/DOCX 导出 -> 回收站恢复。桌面和平板/手机保持相同业务能力，管理页面覆盖账号、模板、模型、审计和受控运维。

2026-10-13 的仓库提供 FastAPI、SQLAlchemy、Alembic 和部分 API 测试；没有 `web/`、前端构建配置、浏览器页面或浏览器验收测试。`docker-compose.yml` 只有应用与 PostgreSQL。现有[任务 07](../.scratch/ai-scriptwriting-platform-v1/issues/07-workspace-and-export.md)的 UI 完成勾选没有前端代码支撑，本任务包重新记录待交付内容，不以原勾选作为验收证据。

已有 API 动作可以复用，但不能据此宣称真实模型创作已完成：[模型适配器](../app/model_adapters.py)的 OpenAI/Anthropic 类继承 Mock，创作对话返回固定文案；正文任务默认排队，需要显式 `/run` 或同步 `auto_run`，没有独立 worker。导出目前同步渲染且历史查询不返回有效下载令牌，选段重写也没有真实选区契约。

## 2. 推荐技术与模块

| 层 | 建议 | 选择理由 |
| --- | --- | --- |
| 应用 | React、TypeScript、Vite | 沿用现有开发设计，构建为静态资源 |
| 路由 | React Router | 认证守卫、作品范围路由、查询参数和错误边界 |
| 服务端状态 | TanStack Query | 查询缓存、mutation、受控轮询和权限变化后的失效处理 |
| 表单 | React Hook Form + Zod | 模板驱动字段与错误关联；最终校验仍在服务端 |
| 正文编辑 | TipTap/ProseMirror 开源基础能力 | 成熟选区、事务、撤销/重做和 IME 支持；自定义语义节点映射结构化正文 |
| UI | CSS 设计变量 + 可访问的基础交互组件 | 使用原生语义元素，弹窗/菜单可采用 Radix；不引入第二套整页样式系统 |
| 图标 | Lucide React | 与页面工具按钮、状态名称保持一致 |
| API 类型 | 从 FastAPI OpenAPI 生成 TypeScript | 降低字段漂移；动态模板仍需要运行时验证 |
| 前端测试 | Vitest、React Testing Library、Playwright | 覆盖编辑器数据边界、流程行为及真实浏览器验收 |

目录建议：

```text
web/
  src/
    app/                 # 路由、认证状态、QueryClient、页面壳
    api/                 # 生成类型、fetch/错误/CSRF处理
    features/
      account/
      works/
      collaboration/
      workspace/
      creative/
      script-editor/
      generation/
      versions/
      releases/
      admin/
    components/          # 字段、状态、菜单、对话框、表格等共用部件
    styles/              # 设计变量、布局、响应式
    test/
  e2e/
  package.json
  vite.config.ts
```

不为一次页面查询建立多层 service/repository。请求、数据转换和业务交互分别放在已有职责清晰的模块；编辑器转换和作品写入协调是需要独立封装的复杂边界。新增 FastAPI 路由沿用既有统一授权与错误工厂，不在前端复制管理员绕过授权分支。

## 4. 关键数据与状态设计

### 4.1 工作区读取模型与能力

保留 `/works/{id}/workspace` 作为首次加载入口，补类型化响应模型与 OpenAPI。建议返回：

```text
work: id, title, work_revision, my_role, settings, template_snapshot
creative: 各阶段 draft、draft_revision、confirmed_snapshot、confirmed_revision、status
permissions: can_edit_draft, can_save_version, can_confirm, can_review_proposals,
             can_grant_consent, can_restore, can_publish, can_export,
             can_manage_members, can_edit_settings, can_trash
input_lock: active_job_id, status, locked_actions
conversations/versions/jobs/releases: 首屏摘要、分页信息或独立查询入口
```

权限描述与实际拒绝来源相同，任务锁定是独立运行状态。大型正文和历史版本按需读取；不要在每次轮询中返回所有历史全文。缓存键含作品 ID，切换作品、退出或授权失效时清除相关内容。

### 4.2 模板驱动表单

服务端把目前多组字段别名转换为一个 canonical schema，前端无需复制后端兼容解析。类型覆盖字符串、数字、整数、布尔、枚举、数组和有限嵌套对象；字段元数据包括 key、中文 label、type、required、default、order、min/max、max_length、items、options 和可选 control。类型对应输入/textarea、stepper、checkbox、select、重复项列表，不把所有值放进文本框。

作品读取自己的锁定定义；模板管理发布新版本不修改旧作品。未知字段/不支持控件返回明确错误，不能静默丢弃数据。旧定义缺中文元数据时由服务端规范化并兼容已知内置字段，不在前端用自由字符串替换猜字段。

### 4.3 编辑器与结构化正文

TipTap 是推荐实现，不要求商业协作插件。自定义集、场景、片段、语义剧本块节点，编辑器文档与 `{episodes -> scenes -> fragments -> blocks}` 双向转换。转换必须保留已有元数据、标识、层级和块类型，空草稿能够初始化；历史版本只读渲染与编辑器共用相同语义映射。

当前片段有 `id`，剧本块尚未要求稳定 ID。拟为当前工作草稿建立稳定块标识及唯一性校验，以支持可靠选区；不可重写不可变历史版本。旧快照以其内容 hash 和结构路径生成只读定位标识，历史恢复时再形成带标识的新版本，迁移过程需保持历史可读。

选段重写拟使用 `fragment_id`、起止 `block_id`、`offset_utf16`、原文 hash 和输入快照 ID。偏移定义与浏览器一致，服务端转为字符串位置并验证 Unicode 边界、连续性和同片段限制；指令不得把一个片段外的文本带入重写目标。成功保留选区前后原文及其他范围，失败/取消/结构错误不产生版本。成熟编辑器处理光标与 IME，服务端处理范围、结构与权限。

### 4.4 写入协调、确认与冲突

正文、各阶段和参数共用作品写入协调器：每次提交取最新 work revision，顺序执行当前用户待提交修改，成功后更新 revision 和相关缓存。自动保存采取防抖，中文合成期间不提交；保存版本、确认、生成前刷新待保存队列，避免不同面板自行猜版本。

协调器只解决单客户端顺序；跨账号并发仍由服务端条件更新/行锁裁定。冲突保存本地缓冲，回读服务器并进入用户选择流程，禁止用新 revision 无条件重发旧正文。遇到生成锁定拒绝时停止写入、读活动任务，不循环重试。

阶段草稿 revision 与已确认快照 revision 分离。提案引用不可变确认快照；普通草稿编辑不改变已确认基线。批准上游提案保留下游草稿和旧确认内容，将当前有效状态变为待重新确认；所有者按顺序重新确认。此处会改变现有提案失效测试，必须按新的业务规则改写，而不是绕过失败测试。

### 4.5 外发与任务状态

拟新增 `POST /works/{id}/input-previews`，接受调用种类、模型、目标、指令或待发送消息；服务端构造并保存外发输入快照，返回不可变标识、摘要、供应商声明及所需确认。增加 `GET /works/{id}/input-previews/{snapshotId}`，在作品访问检查后返回实际拟发送内容、有效性与确认状态；作品内预览链接只定位快照，不能代替登录或授权。外发确认绑定此快照；任务/对话请求复用同一快照，不能授权后偷偷替换指令或扩大内容范围。

任何后续消息形成新的输入快照，即使 work revision 未变也不能复用旧授权。按 ADR-0010，编辑者明确准备后提供预览链接，所有者跨设备确认，编辑者读取确认状态并按原快照发起；准备不调用外部模型、不更新工作草稿。预览保存属于受控作品资料，原文不进入 URL 或日志；配置限制未使用快照的留存，旧快照失效后仍不能沿用授权。首版不增加独立审批请求箱或自动通知。

任务首次提交生成幂等键，网络超时/重复点击复用该键；新的输入或目标生成新键。独立 worker 在外发前、结果提交前检查作品状态、权限、有效确认、模型配置、任务取消和输入版本。任务活动与输入写入锁检查必须在数据库事务中完成，不能先查询再无条件写入。

首版使用轮询，建议 2 秒查询活动任务，后台标签页/离线时暂停或降频，重连后回读；终态停止。尚无进度计数时仅展示状态，不显示百分比。创建时不要求浏览器调用 `/run`，`auto_run` 仅用于受控开发兼容，不能成为页面运行逻辑。正文任务活动时，对话发送也由服务端拒绝，页面保留未发送输入；历史对话查询不受此锁影响。

### 4.6 下载与运维

建议 `POST /exports/{id}/download-link` 每次为所有者签发短令牌并返回地址/到期时间；列表只返状态，不返看似有效的无令牌地址。签发与下载均校验当前所有者权限，所有权变化后原链接不可被原所有者使用。下载可用同源 fetch 获取 Blob 并触发保存，以便处理 401/403/410；令牌和响应正文不进入监测日志。

同步渲染可作为首个阶段；完整交付补真实任务状态、失败重试和存储边界。两个格式仍渲染同一不可变 release。备份恢复需要真实数据库/文件一致性流程、权限与审计；当前快照恢复接口不能作为全系统恢复验收证据，首版运维网页以状态和备份元数据为主。

## 5. 浏览器认证与部署

- fetch 使用同源 `/api/v1`、Cookie 会话；写请求从 `scriptwriting_csrf` 读取值并设置 `X-CSRF-Token`。`scriptwriting_session` 不可被 JavaScript 读取，正文、密码、密钥不存 localStorage。
- 开发：Vite 将 `/api` 与 `/healthz` 代理到本机 FastAPI。现有 `_check_csrf` 比较 Origin 与 API 接收 Host，代理需保持浏览器 Host，不能默认改变 Host 后导致请求被拒绝；用真实浏览器验证登录及写操作。
- 生产：`web` 静态服务/反向代理统一入口，转发 `/api/v1` 与 `/healthz`，可信地保留外部 Host/协议；其他已知前端路由回退 index.html，API 404 不回退 HTML。Cookie Secure 配合 HTTPS，代理信任范围受控。
- Compose 扩展为 `web`、现有 API、worker、db、redis 与受控文件 volume；Node 多阶段构建前端静态资源。迁移、worker 就绪和 API 健康检查有可重复入口。
- 未认证跳登录，`PASSWORD_CHANGE_REQUIRED` 进改密，作品 403/404 进入不可访问状态，不把所有 403 都误判为未登录。修改失败保留当前缓冲，授权失效则隐藏并清除已缓存作品资料。
- 401 后重新登录只能恢复同一账号的当前内存缓冲；用户切换、退出或确认丢弃后清除。HTTP 错误 code 映射中文操作提示，服务端校验错误定位字段。

03/04 可独立推进正文与设定页面，写入协调器和公共契约需先一致；不能在独立实现时各自复制 revision 规则。模型参数页可先完成契约与页面，但真实模型验证必须等 C10/C11/C16；不能通过 Mock 回复标记真实接入完成。

没有固定上线日期或开发人数，不给确定日历承诺。排期评审应单独估算编辑器选区转换、确认快照迁移、真实模型适配和 worker 收口，它们是主要工作量；账号/列表/管理表单可按较小交付块安排。

## 7. 验证与交付标准

| 验证层 | 必须验证的行为 |
| --- | --- |
| 编辑器边界 | 结构往返不丢数据、旧快照可读、中文合成、撤销/重做、同片段跨块选区、Unicode 偏移、范围外内容不变 |
| API/数据库 | 所有角色拒绝矩阵、必须并发版本、原子输入锁、阶段重新确认、不可变提案基础、外发精确快照与权限复核 |
| worker/适配器 | 真实协议的最小请求与流式/非流式解析、结构校验、超时/有限重试/取消/失联恢复，失败不建版本 |
| 浏览器流程 | 首次改密刷新、邀请发现、角色转移、自动保存冲突、远端生成锁定、版本保存/恢复、发布后修改草稿再导出 |
| 下载/运维 | 刷新和过期重新签发、非所有者拒绝、声明和凭证轮换、备份状态不泄露内容，已验证的恢复流程单独验收 |
| 视觉/响应式 | 1440x900、1024x768、390x844 和 360x800 截图；正文、按钮和表单不重叠，软键盘下可提交，全部业务入口可达 |

前端测试避免复制组件内部实现，验证用户看到的内容、交互结果和网络边界。用户在 `to-spec` 发布时已确认：以 Playwright 浏览器完整流程为主要验收入口，连接真实 API、数据库、队列和独立 worker，仅在供应商调用边界使用可控替身；现有 API 行为测试继续覆盖权限、并发与状态规则，不向真实供应商发送测试作品。

最终交付包含 `web/` 与锁文件、前后端契约/生成类型、迁移、Compose 配置、启动文档、自动化验收与可重复截图。建议验证命令为 Python pytest、前端类型检查/测试/build、Playwright 和干净 Compose 启动；前端 scripts 由任务 01 建立，当前仓库尚不能执行这些前端命令。

## 8. 已确认规则对现有实现的影响

- Q4 是对现有 OWNER-only 显式保存的修正；术语表已同步，任务 04 需修改权限与矩阵测试。
- Q5 补充 ADR-0003；ADR-0008 记录取舍，任务 03 需实现有效确认、依赖与历史快照保留。
- Q6 增加全作品输入锁；ADR-0009 记录取舍，任务 05 需涵盖所有写入口而非只禁止前端输入。
- Q7 扩充输入锁至新的外部创作对话；Q8 的预览链接协作由 ADR-0010 记录，任务 05 需支持经过作品授权的不可变快照读取。
- 旧产品规划中“每次修改形成版本”应按 ADR-0003 理解为显式正文保存；自动保存只更新工作草稿。新页面统一用“保存版本”“发布正式稿”“导出”三个命令。
- 页面计划是新增设计基线，既有任务的 resolved 状态不等于新页面验收通过。真实接入、全系统恢复和生产部署必须以对应运行证据判断。
