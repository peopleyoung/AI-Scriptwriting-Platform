# AutoWonder 开发任务包

这是提交给 AutoWonder 的首版开发任务拆分。完整设计见[开发设计文档](./development-design.md)，评审结论见[技术评审报告](./technical-review.md)。

## 任务顺序

| 顺序 | 任务 | 依赖 | 交付重点 |
| --- | --- | --- | --- |
| 1 | 基础工程与 Docker Compose | 无 | 前后端骨架、数据库迁移、健康检查、配置与 CI |
| 2 | 认证、账号和审计 | 1 | Argon2id、会话、首次改密、管理员账号生命周期、审计 |
| 3 | 作品、成员和统一授权 | 2 | 所有权、邀请/撤销、回收站、统一 `WorkAccessService` |
| 4 | 模板和创作资料 | 3 | 模板版本快照、简报、人物、大纲、确认设定、提案 |
| 5 | 版本与生成任务核心 | 4 | 乐观锁、幂等、Redis worker、状态机、重试、取消、冲突 |
| 6 | 模型适配和外发确认 | 5 | 两类接口、凭证加密、同意生命周期、调用元数据 |
| 7 | 协作工作区和导出 | 6 | 三栏工作区、进度、版本比较/恢复、正式稿、Markdown/DOCX |
| 8 | 备份、安全与验收 | 7 | 加密备份、恢复演练、脱敏、权限/并发/合约测试 |

## 统一完成条件

- 遵守 `docs/development-design.md` 的数据、权限、状态机和 API 约束。
- 每个任务包含数据库迁移（如适用）、自动化测试、更新文档和可复现验证命令。
- 不把页面按钮隐藏当作权限控制；所有拒绝场景在 API 层测试。
- 不把 prompt、模型原文、供应商密钥写入日志、审计记录、错误响应或备份清单。
- 通过后续任务前，前置任务的测试和迁移必须在干净 Docker Compose 环境中可复现。

## AutoWonder 交接规则

- 任务 1–5 由全栈开发执行，每个阶段完成后交代码评审。
- 任务 6–7 依赖代码评审通过后继续；涉及模型供应商密钥时使用测试凭证或 Mock，不提交真实密钥。
- 任务 8 在功能完成后执行，包含真实的备份恢复演练；部署目标尚未确定时只做本地 Compose 验收，不宣称生产部署完成。
- 任何权限、外发数据范围、版本语义的需求变更，先更新规划/ADR，再修改代码。
