# 直接配置模型并由创作成员发起调用

状态：产品决策已确认，2026-10-14 模型配置与创作对话访谈 Q1–Q10；已实现。替代 ADR-0004 的逐次外发确认及独立供应商启用说明要求、ADR-0010 的所有者预览审批流程，并调整 ADR-0001 的模型管理入口。完整规则见[模型配置与创作对话设计](../model-chat-design.md)。

管理员直接维护模型的显示名称、接口类型、模型标识、base_url、API key 和可选参数，不再要求先创建独立模型供应商。保留 OpenAI 兼容和 Anthropic 原生协议选择，默认 OpenAI 兼容，因为服务地址和密钥不能可靠推断请求协议。

作品所有者和编辑者可使用管理员启用的模型直接发送创作对话、发起正文生成和选段重写；查看者仍只读。取消“确认本次创作的发送范围”弹窗及逐次所有者审批要求，以减少连续创作和模型切换中的中断；发送区显示当前模型和上下文范围，并允许展开查看，不阻断发送。三阶段设定确认、生成目标与指令仍保留。

点击发送后，立即在对话区显示用户消息及回复占位，逐步呈现模型回复并支持停止。停止或连接中断时保留部分回复，标记已停止或未完成，默认不作为后续模型上下文；失败保留输入并提供手动重试。消息及已保存状态可在刷新后读取。

模型切换继续同一段作品对话，每条回复标明调用模型；选择只影响下一次发送，并按当前用户与作品记住，不改变其他协作者的选择。默认上下文为当前消息、近期对话、创作设定、大纲和当前选中的集、场景或片段；没有正文目标时不附带正文。包含整部正文由发送区选项控制并记住选择，超限明确提示调整，不静默丢弃正文或已确认设定。

每个模型独立启停和维护不可变版本，新增另一模型不退役已有模型。旧模型、密钥、对话和任务记录保留并迁移，已退役版本不自动重新启用。调用绑定发送时的配置版本，管理员更新地址或密钥仅影响后续请求；主动停用模型阻止新调用并停止尚未完成的调用。

同一作品一次只执行一个 AI 调用，其他成员看到忙碌状态并保留输入。正文生成期间继续遵守 ADR-0009 的输入锁；普通对话期间允许编辑正文，回复始终对应发送时的内容快照。

## Consequences

- 编辑者的作品成员授权包含直接发起模型调用的能力，不再等待所有者逐轮审批；作品访问控制和账号启用状态仍由服务端检查。
- 本规则没有赋予管理员读取未获作品授权内容的能力，ADR-0002 保持有效。
- 删除弹窗需要同步调整对话、生成和重试的后端契约，不能通过隐藏前端弹窗或自动伪造所有者授权实现。
- 模型凭证继续由服务端保管，普通作品成员不能读取原密钥；模型调用记录继续遵循 ADR-0005 的元数据记录边界。
- 停止、模型停用、任务终态和同作品并发约束由服务端收口，不依赖页面在线维持；跨模型沿用历史不会改写既有回复的模型归属。

2026-10-24 当前实现边界：本 ADR 赋予 OWNER/EDITOR 的直接模型调用能力，不等于编辑者获得版本管理权限。显式保存版本当前仅 OWNER 有入口（`app/features.py:391-400`），EDITOR 显式保存为产品待定项 pending；恢复、发布正式稿和创建导出仅 OWNER（`app/features.py:434-464,874-877`）；导出下载允许 active 作品成员在 token 未过期时完成（`app/features.py:1126-1138`）。
